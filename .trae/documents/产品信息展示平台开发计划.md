# 产品信息展示平台开发计划

## 一、项目概述

开发一个全栈产品信息展示平台，包含：
- **后端 API**：Node.js + Express + SQLite3
- **Web 管理后台**：纯 HTML + CSS + JavaScript
- **微信小程序端**：原生小程序开发

**核心流程**：运营人员在 Web 端录入产品信息 → 生成统一二维码 → 客户扫码进入小程序 → 搜索查看产品详情

## 三、实施计划

### 3.1 项目初始化

#### 文件：`package.json`
**作用**：定义项目依赖和启动脚本
**内容**：
- 依赖包：express, sqlite3, multer, qrcode, cors
- 启动脚本：`npm start` 运行 server.js

#### 文件：`server.js`
**作用**：后端主入口文件
**核心功能**：
1. Express 服务器配置（端口 3000）
2. 中间件配置（cors、body-parser、静态文件托管）
3. 路由定义
4. 启动时自动创建 uploads/ 目录和数据库表

#### 文件：`database.js`
**作用**：数据库初始化与连接管理
**功能**：
- 创建 SQLite 数据库连接
- 定义 products 表结构
- 导出数据库操作方法

### 3.2 数据库设计

**表名**：`products`

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER | 主键，自增 |
| name | TEXT | 产品名称 |
| description | TEXT | 产品描述 |
| price | REAL | 产品价格 |
| image_url | TEXT | 图片相对路径 |
| unique_code | TEXT | 唯一标识码（PD-时间戳-随机数） |

### 3.3 后端 API 接口

#### POST `/api/products`
**功能**：新增产品
**请求格式**：multipart/form-data
**参数**：name, description, price, image
**处理逻辑**：
1. 使用 Multer 处理图片上传
2. 图片重命名为时间戳格式
3. 生成唯一码（PD-时间戳-随机数）
4. 保存到数据库
5. 返回成功信息

#### GET `/api/products`
**功能**：获取产品列表（支持搜索）
**查询参数**：`search`（可选）
**处理逻辑**：
- 有 search 参数：对 name 和 unique_code 模糊匹配
- 无参数：返回全部产品
- 返回 JSON 格式产品列表

#### GET `/api/product/:code`
**功能**：根据唯一码获取产品详情
**参数**：code（URL 参数）
**返回**：单个产品的完整信息

#### GET `/api/qrcode/entry`
**功能**：生成总入口二维码
**返回**：Base64 格式的二维码图片
**二维码内容**：固定字符串 "product_entry"

**JavaScript 功能**：

## 四、关键实现细节

### 4.1 唯一码生成规则
格式：`PD-{时间戳}-{随机数}`
示例：`PD-1709876543210-1234`

### 4.2 图片上传处理
- 使用 Multer 中间件
- 存储路径：`uploads/`
- 文件命名：`{时间戳}.{原始扩展名}`
- 数据库存储：相对路径 `/uploads/xxx.jpg`

### 4.3 二维码生成
- 使用 qrcode 库
- 内容：固定字符串 "product_entry"
- 格式：Base64 编码图片
- 用途：扫码后进入小程序首页

### 4.4 跨域处理
- 使用 cors 中间件
- 允许小程序前端访问

### 4.5 小程序网络请求
- 使用 `wx.request` API
- 开发阶段在微信开发者工具中勾选"不校验合法域名"

## 七、假设与决策

### 7.1 假设
- 用户已安装 Node.js 环境
- 用户已安装微信开发者工具
- 用户具备基本的微信小程序 AppID（或使用测试号）

### 7.2 设计决策
1. **数据库**：使用 SQLite 轻量级数据库，无需额外安装
2. **文件上传**：使用时间戳命名，避免文件名冲突
3. **二维码内容**：使用固定字符串，便于后续扩展
4. **UI 设计**：简洁实用，优先功能实现
5. **小程序页面**：仅包含首页和详情页，符合最小可行产品（MVP）原则
